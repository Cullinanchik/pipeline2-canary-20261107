# Canary 09 · План замены статуса B

Быстрый механический маршрут: builder, reviewer.

1. Builder выполняет единственную точную замену из TEAM.json.
2. Проверяет AC1 по ожидаемым байтам и AC2 по diff от base; коммитит изменение перед финальной quick-проверкой.
3. Reviewer читает сохранённые актуальные результаты и проверяет AC1–AC3.
4. Полный набор тестов запускает контроллер в Verify. AC3: UAT не нужен.

- AC1: В notes/parallel-b.txt единственное pending заменено на completed; итоговые байты: Synthetic note B: completed.\n.
- AC2: Остальные байты целевого файла и другие файлы приложения не изменены.
- AC3: UAT не требуется; работа ограничена текущим worktree.

На этапе Triage реализация не выполняется.

# Canary 02 · Решение о дизайне и переиспользовании

**Визуальный дизайн не требуется (`required: false`).** Задача меняет только JSON-ответы
`GET /api/items`: фильтр `min_quantity` и ошибку 400. Brief запрещает менять UI. Страница `/`,
`labels.json`, `/health` и ответы 404 остаются байт в байт (SPEC.md R6, AC8). Макеты и Claude Design не
нужны, UAT не нужен.

**Переиспользование (без новых компонентов и зависимостей):**
- `app.py:Handler.do_GET`: существующая маршрутизация и общий путь заголовков. Добавляются только
  переменная `status` и ветка 400 внутри `/api/items` (SPEC.md D7).
- `http.server.BaseHTTPRequestHandler`: стандартный журнал (`log_message`, `log_error`) сохраняется.
  Переопределяется только `log_request`, причём копией стандартного тела: строка запроса проходит
  через новую чистую функцию `app.redact_request_line`, которая обрезает query (SPEC.md R8, D13).
- `api.py:list_items`: источник данных без изменений. Фильтр — новая чистая функция `filter_items`
  поверх него (D2).
- Стандартная библиотека: `urllib.parse.parse_qs` и `urlsplit` для разбора query (D1), `re` для строгой
  проверки цифр (D3), `http.server.ThreadingHTTPServer` и `http.client` для HTTP-тестов (D10).
- `.agent/project.json` и CI: прежние quick и полные проверки, политика не меняется (D11).

**Отклонено:** сторонние фреймворки валидации и роутинга — лишняя зависимость для одного параметра;
изменение сигнатуры `list_items` — brief велит не трогать данные; отключение журнала целиком или
сторонний логгер — шире задачи (D13).

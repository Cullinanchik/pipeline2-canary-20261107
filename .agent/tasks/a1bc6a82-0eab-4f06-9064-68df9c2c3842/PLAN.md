# Canary 02 · План фильтрации синтетического каталога

1. Планировщик фиксирует контракт разбора min_quantity, чистой фильтрации и JSON-ошибки с учётом AC1–AC5. Оппонент проверяет границы и совместимость. Контроллер организует независимое согласование владельца.
2. Разработчик меняет только api.py, app.py и tests/test_api.py: чистая функция (AC2, AC4), HTTP-разбор и статусы (AC1, AC3), проверки (AC5). HTTP-тесты выделить в класс с HTTP в имени для адресного запуска.
3. После коммита разработчик выполняет scripts/agent-check --phase quick и выбранные тесты из TEAM.json. Команды являются планом, в Triage не запускались.
4. Полный набор запускает только контроллер в Verify после завершения сессии и валидной передачи. Ревьюер читает сохранённые проверки.

- AC1: GET /api/items без min_quantity возвращает прежний полный каталог и HTTP 200 JSON.
- AC2: Неотрицательное целое min_quantity=N оставляет только товары с quantity >= N; граница включена, N=0 возвращает все, порог выше максимума возвращает пустой массив.
- AC3: Неверное, пустое, отрицательное, дробное значение и повтор min_quantity дают HTTP 400 JSON с понятной ошибкой.
- AC4: Исходные данные, свежесть возвращаемых значений, UI и остальные маршруты сохраняют прежнее поведение.
- AC5: Добавлены автоматические проверки чистой функции и HTTP поведения для AC1–AC4.

Это оценка области и команды, реализация на этом этапе не выполняется.

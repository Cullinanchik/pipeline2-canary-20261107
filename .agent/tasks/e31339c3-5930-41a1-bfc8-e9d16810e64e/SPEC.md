# Canary 03 · Резервирование синтетических товаров

Предварительная область Triage; реализация не выполнялась.

Источник требований: `.agent/runtime/e31339c3-5930-41a1-bfc8-e9d16810e64e/context/5d011acd4c4ddbd6c52a4b3f0aa18cd2685920f27d94efbc51cdf46bae8b366a.json` (поле content).
Обратная связь: `.agent/runtime/e31339c3-5930-41a1-bfc8-e9d16810e64e/context/b1689e7f3be7f3a01fd541b6166b42bba006c56d3a229a131f737d01666013c9.json`.

- **AC1**: GET /api/items читает сохранённые остатки; начальные Notebook=3 и Pencil=5 сохранены.
- **AC2**: POST /api/reservations создаёт резервацию с item_id, положительным quantity и непустым idempotency_key; некорректные данные отклоняются без записи.
- **AC3**: Повтор ключа с теми же данными возвращает исходную резервацию без повторного списания; другие данные дают 409.
- **AC4**: Конкурентные запросы не делают остаток отрицательным; списание и резервация атомарны.
- **AC5**: Rollback не оставляет частичных изменений; остатки, резервации и ключи сохраняются после рестарта; повторная инициализация не сбрасывает данные.
- **AC6**: Есть проверки гонки, rollback, идемпотентности и восстановления; внешние сервисы, настоящие данные и изменения UI исключены.

Область: app.py, api.py, tests/test_api.py, README.md. Планировщик уточняет необходимость отдельного модуля хранения/миграции и дополнительных тестовых файлов. Только синтетические локальные данные; UI вне области; UAT не требуется.

Открытые вопросы для planner: HTTP-статусы создания/повтора и ошибок, неизвестный товар и недостаточный остаток, формат ответа, типы и ограничения полей, путь SQLite и миграция, блокировки и обработка busy.
